# 팔라독 (프로토타입)

React Native + Expo(SDK 57) + TypeScript. **세로 화면.**

마법 학교 톤의 캐주얼 RPG. 게임은 세 모드로 굴러간다.

- **스테이지** — 유닛을 뽑아 배치하고, 같은 유닛을 조합해 등급을 올려 웨이브를 막는다.
- **협동** — 준비 중
- **PVP 1:1** — 준비 중

방치형 사냥터와 골드 강화는 **없앴다.** 성장은 오직 스테이지 안에서 유닛을 조합하는
것으로만 일어나고, 그 기록이 도감에 남는다.

## 도감 = 조합 기록

도감은 '수집품 목록'이 아니라 **조합해 본 적이 있는가**의 기록이다.
스테이지에서 유닛을 조합해 처음 만들면 그 칸의 잠금이 영구히 풀린다.
아직 설계되지 않은 자리는 `???` 로 잠겨 보인다.

| 등급 | 칸 수 |
| --- | --- |
| 일반 | 5 |
| 희귀 | 4 |
| 영웅 | 3 |
| 전설 | 2 |
| 신화 | 1 |

등급표는 [`src/game/progress.ts`](src/game/progress.ts) 의 `TIERS` / `UNIT_TIER` 에 있다.
**조합 트리는 아직 미정이다** — 지금은 유닛 5종이 전부 '일반'에 들어가 있고
나머지 9칸은 잠긴 자리로만 보인다.

## 아바타 (전설이)

로비 한가운데 서 있는 캐릭터다. **전투력에는 전혀 관여하지 않는다.**
성능을 주면 뽑기가 곧 강함이 돼서 밸런스를 잡을 수 없기 때문에, 등급의 보상은
전부 '로비가 얼마나 화려해지는가' 하나뿐이다. 그래서 단계 사이의 차이가
한눈에 보여야 한다 - 연출을 하나씩 얹는 식으로 쌓는다.

| 등급 | 확률 | 연출 | 중복 환급 |
| --- | --- | --- | --- |
| 일반 | 55% | 없음 | 120 |
| 희귀 | 27% | 오라 | 400 |
| 영웅 | 13% | + 도는 마법진 | 1,200 |
| 전설 | 4.3% | + 반짝이 8 · 배경 광선 | 4,000 |
| 신화 | 0.7% | + 반짝이 12 · 가장 빠른 마법진 | 12,000 |

- 1회 800골드 / 10연 7,200골드. **10연은 희귀 이상 1장 확정**
- 어느 등급이 무엇을 켜는지는 [`src/game/avatars.ts`](src/game/avatars.ts) 의
  `TIER_FX` 한 곳에만 적혀 있다. 연출을 바꾸려면 여기만 고친다

### 별 등급 (중복의 쓸모)

등급이 **어떤 아바타가 나왔나**를 정한다면, 별은 **그 아바타를 몇 장 모았나**를
정한다. 둘은 겹치지 않고 곱해진다.

| 별 | 조건 | 더해지는 것 |
| --- | --- | --- |
| ★ | 1장 | - |
| ★★ | 2장 | 크기 +8%, 반짝이 +3 |
| ★★★ | 4장 | 크기 +18%, 반짝이 +5, 캐릭터 뒤를 도는 별 3개 |

**중복이 그냥 골드로 환급되면 "또 나왔네"로 끝난다.** 별로 쌓이면 "이 녀석
3성 만들고 싶다"는 목표가 생기고, 그게 계속 돌리게 만드는 고리다 (롤토체스
전설이가 이 구조다). 별을 다 올린 뒤부터는 골드로 돌려받는다.

표는 `STAR_FX`, 규칙은 `starOf(copies)` 한 곳에 있다. 보유 상태는 목록과 장수를
따로 두지 않고 **`avatarCopies` 맵 하나**로 관리한다 - 둘로 나누면 어긋난다.

### idle

가만히 서 있으면 그림처럼 보인다. `AvatarStage` 의 `Breathing` 이 위아래로
아주 조금 까딱이면서 살짝 눌렸다 펴지게 한다(1.3초 주기). 이것만으로 살아 있는
것처럼 읽혀서, 3D 모델 없이도 전설이 같은 인상이 난다.

아트는 14종을 파일 14개로 그리지 않는다. 몸은 하나의 통짜 알 모양으로 고정하고
**색 + 귀 + 머리 장식 + 눈**만 갈아 끼운다
([`src/ui/art/avatar.tsx`](src/ui/art/avatar.tsx)). 새 아바타는 `AVATARS` 에
줄 하나만 더하면 바로 그려진다.

### 귀여움은 어디서 나오는가

처음엔 머리와 몸을 **통짜 달걀 하나**로 그렸다. 실루엣이 밋밋하고 눈이 몸 위에
떠 있어 못생겨 보였다. **3D 냐 SVG 냐의 문제가 아니라 뼈대와 음영의 문제였다.**

뼈대 (viewBox 0 0 64 64):

```
머리 장식 0~14 / 귀 5~24 / 머리 9~45 / 몸 33~60 / 발 55~61
```

- **머리(반지름 17 원)가 몸(작은 타원) 위에 얹힌다** - 2등신 아기 비율.
  통짜로 그리면 안 된다
- **머리 안에 밝은 얼굴 바탕**(`belly` 기반 타원) - 눈이 여기 얹혀야 몸에
  떠 있지 않다. 흰색 계열은 머리에 묻히므로 옅은 테두리를 준다
- **부리와 발은 `accent`** - 차가운 몸 색과 대비되는 따뜻한 색.
  이 포인트가 없으면 아무리 칠해도 밋밋하다
- 몸·머리·귀에 **방사형 그라데이션**(왼쪽 위에서 빛), 머리 위 **림라이트**,
  발밑 **접지 그림자**
- 눈은 **크고 새까맣고 하이라이트 하나**. 홍채를 화려하게 굴리는 것보다 이게
  훨씬 귀엽다(전설이·캐주얼 마스코트가 전부 이 방식이다)

> **그라데이션 id 는 아바타 id 로 고유하게 만들 것.** 보유 목록처럼 여러 개를
> 동시에 그리는 화면에서 id 가 겹치면 엉뚱한 색이 나온다.

밟은 것들:

- 작은 슬롯(62px)에서 구분되는지 꼭 확인할 것. 삼각 귀가 너무 작아 외곽선(2.3)이
  안쪽을 다 덮어 **흰 쥐인데 귀만 새까맣게** 보였다. 쥐는 둥근 귀로 따로 뺐다.
- **부리도 같은 함정.** 외곽선 1.7 이 작은 삼각형을 거의 다 먹어서 주황이 조각만
  남았다. 부리를 키우고 선을 1.2 로 줄였다. 부리 안에 넣은 하이라이트 선도
  부리를 통째로 덮어서 뺐다.
- 눈이 붙어 있으면 **부리 자리가 없다.** 좌우로 벌리고(24.3 / 39.7) 살짝 올렸다.
- 팔을 몸 가장자리에 두면 **몸에서 떨어져 보인다.** 안쪽으로 넣었다.
- 모자를 머리 반지름 안에 두면 **파묻힌다.** 머리 위에 얹히게 올렸다.
- `fierce` 눈썹이 눈에 바짝 붙으면 사나워 보인다. 귀여움이 목적이라 짧고
  완만하게, 위로 띄웠다.

## 스테이지 (호위 디펜스)

**플레이어는 소환사다. 팔라독은 조작 대상이 아니라 지켜야 할 대상이다.**
팔라독은 앞이 트인 만큼 알아서 걸어 나간다. 식량으로 유닛을 소환해 그 앞을 막고,
마나로 마법을 써서 길을 열어라. 팔라독이 쓰러지면 그 자리에서 스테이지 실패다.
적 웨이브를 모두 버텨낸 뒤 반격해 적 기지를 부수면 승리.

> 이 전투는 **아직 예전 라인 디펜스 그대로다.** 조합 기반 그리드 디펜스로
> 갈아엎는 것이 다음 작업이다.

## 실행

```bash
npm install
npm start          # QR 찍어서 Expo Go 로
npm run ios        # iOS 시뮬레이터
npm run android    # Android 에뮬레이터
```

**웹은 지원하지 않는다.** 세로 모바일 게임이라 웹으로 낼 계획이 없어서
`react-native-web` / `react-dom` 의존성과 `Platform.OS === 'web'` 분기를 전부
걷어냈다. 덕분에 애니메이션이 조건 없이 네이티브 드라이버로 돈다.

## 로비 (홈)

세로 화면 가운데에 마법사가 서 있고, 양옆에 아이콘 버튼 열이 붙는다.

- **오른쪽 위** — 재화 알약(골드). 아이콘이 알약 왼쪽 밖으로 걸쳐 나오고,
  파란 `+` 를 누르면 얻는 화면으로 간다
- **이름판** — 아바타 이름 + 등급. 테두리가 등급색으로 바뀐다. 누르면 소환으로
- **왼쪽 열** — 관리 · 도감 · 설정
- **오른쪽 열** — 일일 · 소환 · 랭킹
- **가운데** — 아바타. 캐릭터를 눌러도 소환으로 간다. 배경 그림의 바닥 마법진
  위에 서도록 위치를 맞춰 뒀다
- **아래** — 다음 스테이지 카드(= 출정 입구) + 협동 / PVP 1:1

### 배경

> **PNG 가 아니라 JPG 다.** 처음엔 1.1MB PNG 였는데, 다른 화면에 갔다 오면
> 배경이 한 박자 늦게 떴다. RN 의 이미지 캐시는 디코드된 비트맵 크기로
> 재는데 PNG 는 압축을 풀면 2MB 를 넘겨 캐시에서 매번 쫓겨났다. 386KB JPG
> 로 바꾸고, `App.tsx` 에서 프리페치하고, 그림이 오기 전에는 배경에서 뽑은
> 색 띠 그라데이션을 깔아 '무배경' 상태 자체를 없앴다. 셋 다 필요했다.

`assets/background.jpg` (1206x2710) 한 장 위에
[`HomeBackdrop.tsx`](src/ui/HomeBackdrop.tsx) 가 움직이는 레이어를 얹는다 —
**바닥 마법진 숨쉬기 + 그 위로 피어오르는 빛먼지.** Lottie 나 동영상 대신
이렇게 하는 이유: Lottie 는 SDK 57 문서에서 빠져 dev build 가 필요하고
(Expo Go 이탈), 동영상은 용량과 배터리를 먹는다. 코드로 얹으면 용량이 0 이고
Expo Go 에서 그대로 돈다.

**창(밤하늘) 쪽에는 아무것도 움직이지 않는다.** 별 깜빡임과 유성을 넣어 봤는데
이미 그려진 하늘 위에 겉도는 점처럼 보여서 뺐다. 빛먼지도 창까지 떠오르지 않게
상승 거리를 줄였다. 움직임은 바닥에만 둔다.

레이어 좌표는 전부 **그림 안에서의 비율**이다(`SEAL` 상수). 그림과 똑같은
크기/위치의 View 에 겹쳐 놓기 때문에 화면 크기가 달라져도 빛먼지가 마법진
위에 정확히 얹힌다.

> **크기는 `useWindowDimensions` 로 직접 계산한다.** `resizeMode` 나
> `left/right/bottom + aspectRatio` 에 맡기면 안 된다 - 후자는 높이가 안 잡혀
> 그림이 통째로 확대돼 버린다(실제로 밟았다).
>
> **폭을 화면에 맞춘다.** 좌우 기둥이 온전히 남는다. 세로를 채우는 방식도
> 써 봤는데 좌우가 9% 씩 잘려 기둥이 얇아졌고, 폭에 맞춰 아래로 붙이는
> 방식은 위가 남아 이음새가 보였다.
>
> **그림은 원본이 아니라 아래를 늘려 붙인 1206x2710 이다.** 원본
> 그대로 폭에 맞추면 세로가 화면보다 짧아 아래가 비고, 무엇보다 **마법진이
> 그림의 73% 지점이라 캐릭터가 화면 아래로 쏠린다.** 아래에 바닥을 350px
> 이어 붙이면 마법진이 58% 로 올라와 캐릭터가 화면 정중앙에 선다.
> 새 배경으로 갈 때 같은 처리를 하려면:
>
> ```python
> from PIL import Image
> im = Image.open('assets/background.jpg').convert('RGB')
> W, H = im.size
> ADD = 350   # 마법진이 화면 중앙에 올 때까지 조절
> strip = im.crop((0, H - 120, W, H)).resize((W, ADD), Image.LANCZOS)
> out = Image.new('RGB', (W, H + ADD)); out.paste(im, (0, 0)); out.paste(strip, (0, H))
> out.save('assets/background.jpg', quality=88)
> ```
>
> 마법진 좌표(`SEAL`)는 눈대중하지 말고 노란 선 픽셀 범위를 실제로 재서 넣는다.
> 그림을 가운데 두는 게 아니라 **마법진이 화면 정중앙에 오도록** 배치한다
> (`left: screenW / 2 - bgWidth * SEAL.x`).

> **배경은 노치 뒤까지 꽉 차야 한다.** `App.tsx` 의 루트가
> `paddingTop: insets.top` 으로 안전영역만큼 안으로 밀어 놓기 때문에, 그냥
> 두면 그림이 노치 아래에서 시작해 위가 잘려 보인다. `HomeScreen` 이
> `useSafeAreaInsets()` 로 그 패딩을 음수 좌표(`top: -insets.top`)로 되돌려
> 화면 전체를 덮는다.

아바타는 그림 속 마법진 위에 서도록 `HERO_SHIFT` 만큼 내리고, 배경이 위로
올라간 만큼(`- insets.top`) 같이 올린다. 배경 그림을 바꾸면 이 값과
`HomeBackdrop` 의 `SEAL` 좌표를 같이 맞춰야 한다.

출정 입구는 **카드 하나뿐이다.** 예전에는 카드 아래에 '스테이지' 버튼이 따로
있었는데 같은 곳으로 가는 입구가 둘이라 헷갈려서 버튼을 없앴다.

설정·랭킹·협동·PVP 는 아직 "준비 중" 안내만 띄운다.

## 매일 돌아오는 것

## 밸런스 조정

`src/game/balance.ts` 와 `content.ts` 를 고친 뒤 **반드시** 시뮬레이터를 돌릴 것.

```bash
npm run sim              # 전 스테이지, 7회 시행 승률
SIM_UNITS=mouse npm run sim -- s1     # 해금 상태를 흉내내 첫 플레이 검증
SIM_RUNS=15 npm run sim  # 시행 횟수 늘리기
npm run sim -- sweep     # 난이도 배율을 훑어 승패 경계 찾기
npx tsx tools/trace.ts s1 1   # 한 판을 10초 간격으로 추적
```

현재 기준선 (7회 시행 승률, 배율 고정):

```
  무너진 성문       7/7
  안개 늪지        7/7
  검은 언덕        7/7
  리치의 제단       1/7
  왕좌의 문        0/7
```

**s4/s5 는 지금 못 깬다.** 예전에는 골드 강화로 뚫는 구조였는데 강화를 없앴으니,
조합으로 강해지는 새 전투가 들어오면서 다시 잡아야 한다.

### 설계하면서 시뮬레이터가 잡아낸 것들

이 게임의 밸런스는 직관이 여러 번 틀렸다. 기록해 둔다.

1. **아군 유닛이 무한히 쌓이면 전선이 적 기지에 못 박힌다.** → 부대 정원(12기) 도입.
2. **적을 한 마리씩 흘려보내면 아무리 자주 보내도 소용없다.** 아군은 뭉쳐 있어서
   도착 즉시 녹는다. → 묶음 웨이브로 변경.
3. **한 줄로 세우면 아무리 많이 소환해도 1:1 싸움이 된다.** `minGap` 때문에 선두
   1기만 적에게 닿는다 (실측: 평균 동시 교전 1.0기, 최대 1기).
   → 전열(`LANES`)을 나눠 같은 열끼리만 길을 막게 했다. 3열이면 평균 2.2기,
   최대 6기가 동시에 때린다. `npx tsx tools/gang.ts` 로 잴 수 있다.
   단, **양쪽 다 3열로 두면 안 된다** — 적은 웨이브로 머릿수가 더 많아서 오히려
   플레이어가 불리해진다(실측: 3~5스테이지 승률 0%). 아군 3열 / 적 2열로 뒀다.
4. **적이 무한히 밀려오면 판이 영원히 안 끝난다.** 실력이 비슷하면 7분이 지나도
   교착이었다. → 웨이브를 유한하게 만들고, 다 버티면 반격해 이기는 구조로 변경.
5. **대열 간격(`minGap`)이 근접 사거리보다 커지면 선두 1기만 싸운다.** 캐릭터 그림을
   키우려고 간격만 넓혔더니 아군 전투력이 반토막 나 후반 스테이지가 교착에 빠졌다.
   → 간격만 넓히지 말고 `FIELD_LENGTH`·사거리·이동속도를 같은 비율로 함께 키울 것
   (시간 값은 그대로라 밸런스가 보존된다).
6. **팔라독이 전선에 바짝 붙어 따라가면 강해질수록 더 자주 죽는다.** 부대가 세지면
   전선이 빨리 전진하고, 팔라독도 그만큼 깊이 끌려 들어가 전선이 무너지는 순간
   그대로 맞아 죽었다. 강화 8레벨이 4레벨보다 승률이 낮은 역전이 실제로 났다.
   → `HERO.escortGap`(235px) 완충 거리를 둬서 항상 전선 뒤를 따라가게 했다.
   **조합으로 유닛이 세지는 새 구조에서도 똑같은 함정이 있다.**
7. **한 판만 돌려보고 튜닝하면 안 된다.** 웨이브 편성이 무작위라 표본 1개로는
   방향을 잘못 잡는다. `SIM_RUNS`(기본 7회) 승률로 판단할 것.

## UI 스타일

**마법 학교 톤** — 깊은 밤하늘 남보라 + 금색 장식 + 양피지 + 자주빛 강조.
저작권 문제를 피하려고 특정 작품의 이름·문장·기숙사 색은 쓰지 않고, '마법 학교'
라는 일반적인 분위기만 가져온다. 이 원칙은 [`src/ui/theme.ts`](src/ui/theme.ts)
맨 위에도 적어 뒀다.

공용 부품은 [`src/ui/components.tsx`](src/ui/components.tsx) 에 있다.

| 부품 | 쓰임 |
| --- | --- |
| `Frame` | 패널 (외곽선 → 금색 실선 → 결 → 상단 광택) |
| `Banner` | 패널 위에 걸치는 리본 제목 |
| `Slot` | 움푹 파인 아이콘/아이템 칸. `locked` / `rarity` 지원 |
| `Button` | 아랫면에 어두운 두께를 깐 입체 버튼 |
| `CoinPill` | 재화 알약 — 아이콘이 왼쪽 밖으로 걸쳐 나오고, `onPlus` 를 주면 파란 + 뱃지가 붙어 얻는 화면으로 보낸다 |
| `IconButton` | 아이콘 타일 + 아래 라벨 + 알림 뱃지 (로비 아이콘 열) |
| `ScreenHeader` | 팝업 상단 바 — 아이콘·제목·재화·✕ |
| `VTabs` | 좌측 세로 탭 (뱃지 지원) |

색은 [`src/ui/theme.ts`](src/ui/theme.ts) 의 `C` / `G` / `RARITY_G` / `EDGE` 에 모여 있다.
어두운 이모지를 슬롯에 넣으면 배경에 묻히니 주의할 것.

**슬롯 안에 SVG 를 넣을 때 주의**: 슬롯 배경을 `position:absolute` 레이어로 깔면
그 레이어가 SVG 아트 위에 얹혀 캐릭터가 통째로 사라질 수 있다(이모지 Text 는
멀쩡해서 놓치기 쉽다). 그래서 `Slot` 은 LinearGradient 자체를 컨테이너로 쓰고
내용물에 `zIndex: 1` 을 준다.

### 애니메이션

로비 연출은 `Animated` 로 돌린다. 전부 `transform` 과 `opacity` 만 쓰므로
`useNativeDriver: true` 로 GPU 에서 돌아가고 JS 스레드를 쓰지 않는다.
`AvatarStage` 최대 15개 + `HomeBackdrop` 20개가 동시에 돌지만 실기 부담은 거의
없다.

움직이는 배경을 넣는 다른 방법들과 비교한 결과는 위 '배경' 절에 적어 뒀다.
정리하면 **Lottie 는 SDK 57 문서에 페이지가 없어 dev build 가 필요**하고,
`expo-gl`(three.js) 과 `expo-image`(애니메이션 WebP/GIF/APNG) 는 Expo Go 에서
동작한다.

### 실제 해상도

노치 폰의 안전영역이 빠지므로 콘텐츠 크기는 **세로 393x760**이다
(가로로 돌리면 852가 아니라 **754x393** — 좌우에서 약 59+34px 이 빠진다).
852 로 테스트하면 멀쩡하다가 실기에서 라벨이 잘린다. 화면을 고칠 때마다
iOS 시뮬레이터에서 확인할 것.

```bash
xcrun simctl io booted screenshot shot.png   # 1206x2622
```

**아직 세로로 안 고친 화면이 있다.** `UnitScreen` / `MissionScreen` 은 3단
가로 배치라 세로에서 좁게 눌린다. 전투를 갈아엎으면서 같이 손봐야 한다.

### 세로 고정

`app.json` 의 `"orientation": "portrait"` 만으로는 **Expo Go 에서 안 걸린다.**
`App.tsx` 가 `expo-screen-orientation` 의
`lockAsync(OrientationLock.PORTRAIT_UP)` 을 직접 호출해야 한다. 둘 중 하나만
바꾸면 조용히 예전 방향으로 뜬다(실제로 한 번 놓쳤다).

## 폰트

앱 전체가 **배달의민족 주아체**(`assets/BMJUA_otf.otf`) 하나로 간다.

Expo 에는 '앱 전역 기본 폰트' 설정이 없고, React 19 부터는 함수 컴포넌트의
`defaultProps` 가 무시돼서 예전에 쓰던 `Text.defaultProps` 꼼수도 안 통한다.
그래서 [`src/ui/Text.tsx`](src/ui/Text.tsx) 가 RN 의 `Text` 를 한 번 감싸
`fontFamily` 를 앞에 깔아 두고, 화면들은 `'react-native'` 대신 **이 파일에서
`Text` 를 가져다 쓴다**. 새 화면을 만들 때도 여기서 import 할 것.

### 이 폰트에서 밟은 함정 둘

1. **빈 글리프.** `·` `•` `—` `ㆍ` 는 cmap 에는 있는데 **외곽선이 없어서**
   화면에 공백으로 나온다. 폰트를 바꾸기 전엔 구분자로 `·` 를 썼는데 전부
   사라져 보였다. 지금은 `|` 와 `-` 로 바꿔 뒀다. 새 구분자를 쓸 땐 먼저 확인할 것:

   ```bash
   python3 -c "
   from fontTools.ttLib import TTFont
   from fontTools.pens.boundsPen import BoundsPen
   f=TTFont('assets/BMJUA_otf.otf'); cm=f.getBestCmap(); gs=f.getGlyphSet()
   for ch in ['·','|','-']:
       g=cm.get(ord(ch)); pen=BoundsPen(gs)
       if g: gs[g].draw(pen)
       print(ch, '있음' if pen.bounds else '빈 글리프')
   "
   ```

   (글자 폭을 재는 방법은 못 쓴다 — 없는 글자도 폴백 폰트로 그려져 폭이 나온다.
   반드시 위처럼 **외곽선**이 있는지를 봐야 한다.)

2. **폰트 이름이 두 개다.** `useFonts` 에 넘긴 키는 `BMJUA` 인데 파일 내부
   이름은 `BM JUA OTF` 다. 지금은 `useFonts` 가 키로 등록해서 맞지만,
   `expo-font` config plugin(빌드 타임 내장)으로 바꾸면 iOS 가 내부 이름으로
   등록해 **조용히 시스템 폰트로 떨어진다.**

주아체는 굵기가 하나뿐이라 `fontWeight: '900'` 은 실제로 굵어지지 않는다.
iOS 에서 폴백 없이 정상 렌더되는 건 확인했다.

## 아트

캐릭터·배경은 전부 `react-native-svg` 로 직접 그렸다 (`src/ui/art/`). 이미지 파일이
없어서 확대해도 안 깨지고, 색만 바꿔 변형을 만들 수 있다. 규칙은 세 가지다.

- viewBox 는 `0 0 64 64`, 발밑이 y=60
- 전부 **오른쪽을 보는** 자세로 그린다 (적은 렌더할 때 `scaleX: -1` 로 뒤집음)
- 외곽선은 `OL`(#181324) / `SW`(2.3) 로 통일해 한 세트처럼 보이게 한다

로비 마법사(`art/wizard.tsx`)는 세로 예산을 정해 두고 그렸다 —
모자 2~23 / 머리 22~42 / 로브 40~60. 이걸 안 지키면 모자 끝이 viewBox 밖으로
나가 잘린다(실제로 한 번 잘렸다).

새 유닛을 추가하려면 컴포넌트를 하나 그리고 `characters.tsx` 의 `REGISTRY` 에
`defId` 로 등록하면 끝이다.

## 저장

`AsyncStorage` 한 칸(`paladog:meta:v2`)에 `MetaProgress` 를 통째로 넣는다.
읽을 때 `sanitize()` 로 형태를 강제하므로 저장본이 깨져도 앱은 뜬다.
필드를 없앨 때는 `META_VERSION` 을 올릴 것 (지금 6 — 아바타 별 등급).
정의가 사라진 아바타 id 는 `sanitize()` 가 걸러 내고, 장착 중이던 것이
사라졌으면 갖고 있는 것 중 하나로 되돌린다.
